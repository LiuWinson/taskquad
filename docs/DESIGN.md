# TaskQuad 设计规范（Web 与鸿蒙端共同遵守）

应用名称：**任务四象限**（TaskQuad）。界面语言：简体中文。

## 1. 四象限配色与含义

| key | 标签 | 主色 | 含义 |
| --- | --- | --- | --- |
| IU | 重要且紧急 | `#E5484D`（红） | 立即处理 |
| IN | 重要不紧急 | `#3B82F6`（蓝） | 计划安排 |
| NU | 紧急不重要 | `#F59E0B`（琥珀） | 尽快处理/委托 |
| NN | 不重要不紧急 | `#8B8F98`（灰） | 空闲时处理 |

四象限看板布局（重要=上行，紧急=左列）：

```
+----------------+----------------+
| IU 重要且紧急  | IN 重要不紧急  |
+----------------+----------------+
| NU 紧急不重要  | NN 不重要不紧急|
+----------------+----------------+
```

## 2. 页面结构

### 顶部导航
应用标题「任务四象限」+ 视图切换：**四象限** / **列表** / **归档**（宽屏另有右侧「每日计划」栏，窄屏显示为第 4 个标签「计划」），右侧设置入口（齿轮图标/「设置」）。

### 视图一：四象限看板
- 2×2 网格，每个象限一个卡片：色条 + 象限名 + 未完成任务数。
- 卡片内任务行：勾选框（完成打钩）+ 标题 + 截止时间徽标 + 象限色点缀。
- 已逾期（`dueAt < now` 且未完成）的截止时间用红色加粗显示。
- 每个象限卡片底部「+ 添加任务」按钮（新增时自动带入该象限）。
- 顶部提示文案：按住任务可拖动排序/换象限。

#### 拖拽交互（桌面端/浏览器，HTML5 Drag & Drop）
- 任务行 `draggable`；拖动中该行 40% 透明度，悬停的目标象限卡片显示虚线边框。
- 拖到某任务行上方/下方：该行顶部/底部显示插入指示线，松手插入该位置。
- 拖到卡片空白区（含空卡片）：追加到该象限末尾。
- 拖到右侧「每日计划」的某个半小时槽位：排入当天该时间段（30 分钟起）。
- 计划块可拖回四象限（= 移出计划）、也可拖到计划内其他槽位（移动时间段）。
- 提交方式：`PATCH /api/tasks/:id { "quadrant": <目标象限>, "order": <排序值> }`，order 取相邻两项中点（首位置 = 前项-1，末位置 = 末项+1，空列表 = 当前时间戳）；同象限排序仅提交 `order`。从计划拖回象限时额外提交 `planDate: null`。
- 排序语义：每个象限内按 `order` 升序展示（旧数据由服务端以 createdAt 时间戳补齐）。
- 移动端（<640px）：触屏设备无原生拖拽，通过点按计划空槽位弹出任务选择列表完成排期。

### 视图二：列表视图
- 未完成任务按 `dueAt` 升序，无截止时间排在最后。
- 每行：勾选框 + 标题 + 象限彩色小标签 + 截止时间（逾期红色）+ 提醒时间（如有，显示小铃铛）。
- 顶部「+ 新建任务」按钮。

### 视图三：归档视图
- 子标签切换：**本周 / 本月 / 本季度**（对应 `GET /api/archive?period=`）。
- 已完成任务按完成时间降序，可按天分组（显示「M月d日」分组头）。
- 每行：标题 + 象限标签 + 完成时间。
- 操作：**恢复**（`PATCH completed=false`，任务回到看板/列表）、**删除**。
- 顶部显示该周期完成数量（如「本周已完成 5 项」）。

### 视图四：每日计划（右侧栏；宽屏 ≥900px 常驻，窄屏为「计划」标签页）
- **半小时粒度时间轴（工作时段）**：07:00-23:00 共 32 个槽位，每小时整点有刻度与时间标签；今天有红色「现在」线（仅工作时段内显示）。23:00-07:00 不显示、不可排入。
- 头部：前一天/后一天切换、日期显示（今天 · M月d日 周X）、回到今天、当日计划数。
- **排期**：桌面端把四象限任务拖到槽位即排入 30 分钟（占用该半小时）；槽位悬停高亮，与已有计划块冲突时（时间重叠）红色警示并拒绝。窄屏/触屏点按空槽位 → 弹出任务列表选择排入。
- **调整时间段**：
  - 计划块整体拖动到其他槽位（移动，时长不变）；**保持抓取点**（从块中间抓住拖动，落点按抓住的相对位置对齐，不再跳格）。
  - 计划块上下边缘鼠标拖拽缩放（30 分钟步进、实时预览、松手提交）。
  - 点击计划块弹出编辑层，可改开始/结束（30 分钟步进的下拉）、应用。
- **Ctrl 多选与批量调整**：Ctrl+点击计划块多选（蓝色描边，Esc 取消）；顶部工具条「前移/后移 30 分钟、取消选择」；拖动任一选中块 = 全部选中块按相同时间差整体移动。批量拖动时显示所有选中块的**投影预览**（幽灵块 + 目标时间段），位移为零时不显示投影，超出工作时段或与其他块冲突时红色警示并拒绝。
- **完成反馈**：
  - 计划块显示时间范围；已反馈显示「· xx%」。
  - **待反馈状态**：今天、计划结束时间已过、未完成、未反馈 → 计划块红色脉冲高亮 +「⏰ 待反馈」角标；服务端同时弹一次 Windows 桌面通知「时间段已结束，请反馈完成情况」。
  - 反馈方式（编辑层内）：滑块/快捷按钮（25/50/75/100%）选择完成百分比 →「保存进度」；或「✓ 直接完结」（`PATCH completed=true`，进入归档）；也可「移出计划」。
- 已完结任务不再显示为计划块（归档中可恢复，恢复后计划块重现）。
- 计划块配色：左边框取任务象限主色；象限卡片与列表中对已排期任务显示 📅 徽标（含时间段）。
- 拖拽事件统一在时间轴容器按指针坐标换算槽位（不依赖槽位元素命中），保证投影平滑按格移动。

#### 循环任务（视图四内）
- 计划块编辑层设「循环」：不循环 / 每天 / 每周 / 每月 / 每季度（`PATCH repeat`）。
- 规则：`planDate` 为基准日；daily=每天；weekly=同星期几；monthly=同号（目标月不足取月末）；quarterly=同季同号。仅命中且不早于基准日的日期显示该块。
- 循环块标题带 🔁 前缀，meta 显示循环类型；象限/列表徽标用 🔁。
- **按天独立反馈**：完成百分比、完结、待反馈提醒均按「当天」记录（`occurrences[日期]`），互不影响；任务本体保持未完成、持续循环。
- 循环块整体拖动/缩放只改时间段，**不改变基准日**；「停止循环并移出」= `repeat:none` + `planDate:null`。

### 编辑/新建任务对话框
字段：
1. 标题（必填）
2. 备注（多行，可选）
3. 四象限（4 个可选色块，单选，默认 IU）
4. 需要完成时间（截止时间，日期+时间选择，可留空）
5. 提醒时间（日期+时间选择，可留空；Web 端提供快捷按钮：截止前 5 分钟 / 15 分钟 / 1 小时 / 1 天——仅在已选截止时间时可用）
6. 操作：保存 / 取消；编辑已有任务时另有删除按钮。

勾选完成交互：点击勾选框立即调用 `PATCH completed=true`，行样式变为删除线/变灰后移入归档（无需确认）。

### 番茄工作法（1.4.0 / 1.4.1）
- 入口两处：①「编辑任务」对话框内「🍅 开始番茄」；②**右侧「每日计划」点击计划块 → 编辑层「🍅 开始番茄」**（编辑层同时显示该任务番茄统计与最近打断原因）。
- 顶部橙色番茄条：任务名 + 倒计时 mm:ss + 进度条 +「完成番茄」「打断」。
- **同一时刻只允许一个进行中的番茄**（服务端 409 拒绝第二个）。
- **打断必须写清原因**：点「打断」弹出必填文本框，原因存入该番茄记录（≤200 字）。
- 恢复后重新开始 = **新建一个番茄**（原番茄记为 interrupted，保留原因历史）。
- 到点自动完结并弹 Windows 通知「番茄完成，休息一下」；任务对话框内显示「已完成 N 个 · 打断 M 次（最近原因）」。
- **番茄时长可配置**（设置 → 番茄工作法）：工作时间（默认 25 分钟，开始番茄时使用）、短休息（默认 5 分钟）、大休息（默认 15 分钟）、每几个番茄后大休息（默认 4 个）。
- **休息阶段**：完成一个番茄后自动进入休息条（绿色=短休息、蓝色=大休息），倒计时结束提示「可以开始下一个番茄」，可「跳过休息」或直接「开始下一个番茄」（同一任务）。大休息按当天已完成番茄数是否达到 `longBreakEvery` 的整数倍判定。
- 报告视图会把番茄完成/中断数量作为投入参考写入素材。

### 报告视图（1.4.0）
- 顶部标签页「报告」（宽屏窄屏都显示），三个子标签：日报 / 周报 / 月报；「生成报告」按钮。
- 素材：**上一周期已完成任务**（daily=前一日、weekly=上周、monthly=上月）+ **本周期计划**（含每日计划时间段、循环投射、截止时间），按四象限优先级排序。
- 生成结果以纯文本展示（保留 Markdown 原文），带「复制报告」；生成中显示等待提示（通常十几秒）。
- 使用前需在「设置 → 大模型」配置 OpenAI 兼容接口（地址/模型/API Key），并提供「测试连接」。
- **报告风格 Skill**（设置 → 报告风格 Skill）：可编辑的写作风格说明，默认文案填在输入框内供参考修改；生成报告时作为「报告风格要求」发给大模型；「恢复默认」清空自定义。
- **升级保留个人配置**：大模型配置、Skill、番茄设置均存于数据目录 `config.json`，覆盖安装不覆盖；Skill 自定义优先于默认；保存的内容与默认一致时自动视为「使用默认」（不会把默认文案钉死成自定义，后续默认更新仍可生效）。
- 大模型配置与 Skill 仅存本机 `config.json`，接口不回传密钥。

## 3. 设置与连接（鸿蒙端）

- 鸿蒙端需要配置服务器地址：`http://<Windows 局域网 IP>:8788`，保存到本地偏好。
- 提供「测试连接」按钮（调用 `GET /api/health`），成功显示绿色提示，失败显示红色错误。
- 主界面顶部显示连接状态（已连接/未连接）。
- 默认端口 8788。

## 4. 视觉风格

- 浅色背景（`#F5F6F8`），白色卡片，圆角 12px，细边框，轻投影。
- 主色点缀使用象限色；主操作按钮可用深蓝 `#2F6BFF` 或中性深灰。
- 已逾期时间：红色 `#E5484D` 加粗。
- 完成任务：标题删除线 + 60% 透明度。
- 字体：系统默认无衬线字体。移动端（<640px）四象限网格退化为单列。

## 5. 鸿蒙端提醒机制

- App 每次同步到任务列表后，本地对账提醒：
  - 未完成且 `remindAt` 在未来 → 用 `reminderAgentManager` 发布 `ReminderRequestTimer`（`triggerTimeInSeconds = remindAt/1000`），`title = 任务提醒`，`content = 任务标题`。
  - 已完成、无 `remindAt`、或 `remindAt` 已过 → 取消对应 reminderId。
  - reminderId 由任务 id 稳定哈希得到（正整数，< 2^31）。
- 首次启动请求提醒权限（`ohos.permission.PUBLISH_AGENT_REMINDER`，module.json5 中声明）。
- App 在前台每 30 秒刷新一次任务列表；进入页面时立即刷新。

## 6. 鸿蒙端工程约定

- Stage 模型，DevEco Studio 5.x，`modelVersion: "5.0.0"`，`compatibleSdkVersion: "5.0.0(12)"`。
- bundleName：`com.example.taskquad`。
- 所有 .ets 源文件严格 ArkTS 语法（禁止 `any`、禁止未类型化对象字面量、禁止解构、`as` 断言需注意）。
- 网络权限 `ohos.permission.INTERNET`、提醒权限 `ohos.permission.PUBLISH_AGENT_REMINDER` 在 module.json5 声明。
